# Task 2 — Marketing data pipeline

Python pipeline for cleaning raw LinkedIn-style marketing contact data and selecting **one senior marketing leader per company**.

This task is independent from `task1-fullstack`.

## Project layout

```text
task2-data-pipeline/
├── pipeline.py
├── requirements.txt
├── linkedin_raw_data.csv
├── marketing_contacts_clean.csv   # Generated by `python pipeline.py` (committed for submission)
├── src/
│   ├── config.py       # Placeholders, personal-email domains, markers
│   ├── inspect.py      # Dataset inspection / profiling
│   ├── utils.py        # Base text normalization helpers
│   ├── clean_names.py  # Contact name cleaning
│   ├── clean_titles.py # Job title extraction from headlines
│   ├── clean_company.py # Company display + grouping keys
│   ├── clean_email.py  # Email validation, personal-domain flag, LinkedIn URLs
│   ├── cleaning.py     # Orchestrates steps and derived keys
│   ├── roles.py        # Include / exclude marketing leadership rules
│   ├── classify_roles.py # Target flag, role category, seniority_rank
│   ├── filter_rows.py  # Irrelevant rows (sponsored, non-target, bad keys)
│   ├── deduplicate.py  # One row per (person, company)
│   └── selection.py    # One row per company + export
└── README.md
```

## Run

From `task2-data-pipeline/`:

```bash
python pipeline.py
```

The script loads `linkedin_raw_data.csv`, prints an inspection summary, and overwrites `marketing_contacts_clean.csv`. No manual edits are required.

## Inputs and outputs

| Role | File |
|------|------|
| Input | `linkedin_raw_data.csv` |
| Output | `marketing_contacts_clean.csv` |

The output CSV has **exactly** these columns:

- `company_name`
- `contact_name`
- `job_title`
- `email` — corporate address only; **empty string** if missing or only a personal-domain address is available after deduplication
- `linkedin_url` — full `https://…linkedin.com/in/…` URL or **empty string**

## Pipeline stages (high level)

1. **Load** raw CSV (paths relative to `pipeline.py`).
2. **Inspect** — shape, dtypes, missing counts, sample values (`src/inspect.py`).
3. **Base normalize** — `src/utils.py::normalize_text_fields()` applies generic cleanup to raw text columns (`raw_name`, `headline`, `company_name`, `location`, `profile_url`, `email`): trim, collapse repeated spaces, decode HTML entities, normalize dash variants, and map empty-like placeholders to empty strings.
4. **Contact names** — `src/clean_names.py::clean_names()` produces `contact_name_clean` (honorifics, casing, invalid placeholders).
5. **Per-column whitespace** — inside `clean_raw_dataframe`, raw text columns are normalized again for stable parsing.
6. **Job titles** — `src/clean_titles.py::extract_job_titles()` sets `job_title_clean` from `headline` using rules: take text before the first `|`, then strip a trailing `at Company` chunk when the tail is short (heuristic for “Title at Company”).
7. **Company names** — `src/clean_company.py::standardize_company_names()` sets `company_name_clean` from `company_name`, or from headline patterns `Title at Company` / `Title - Company` when the company field is empty; light proper casing and brand aliases; `company_key` is derived from `company_name_clean` for grouping (see `company_group_key()`).
8. **Emails & LinkedIn** — `src/clean_email.py::clean_emails()` sets `email_normalized`, `email_valid`, `email_is_personal` using `email-validator` (syntax only, `check_deliverability=False`) and `tldextract` on the host to get a registrable domain, compared to `PERSONAL_EMAIL_DOMAINS` in `config.py`. Values that look like phone numbers in the email column are rejected. `normalize_linkedin_urls()` sets `linkedin_url_clean` to a full `https://…linkedin.com/in/…` URL or empty string.
9. **Role classification** — `src/classify_roles.py::classify_roles()` sets `is_target_role`, `role_category`, and `seniority_rank` using `ROLE_INCLUDE_KEYWORDS` / `ROLE_EXCLUDE_KEYWORDS` and `SENIORITY_LEVEL_PATTERNS` in `config.py`. Non-target rows get `seniority_rank = 0`.
10. **Filter irrelevant rows** — `src/filter_rows.py::remove_irrelevant_rows()` drops sponsored/invalid-name rows, requires non-empty `contact_name_clean` / `company_name_clean` / `company_key`, and keeps `is_target_role == True` when present.
11. **Deduplicate** — `src/deduplicate.py::deduplicate_profiles()` keeps one row per `(name_key, company_key)`; `scraped_at` is parsed with `dateutil`; tie-break order is recency, corporate email, LinkedIn presence, seniority, shorter derived title, then name.
12. **Select** — `src/selection.py::select_one_row_per_company()` picks one row per `company_key` using seniority, corporate email, LinkedIn, recency.
13. **Write** final five-column CSV.

`pipeline.py` runs base normalize and `clean_names` before `clean_raw_dataframe`; title and company steps run inside `clean_raw_dataframe` **after** per-column whitespace so `headline` / `company_name` match what downstream parsers expect.

## Business rule configuration

Core rules are centralized in `src/config.py` so the pipeline stays deterministic and easy to review:

- **Placeholder values** — `PLACEHOLDER_VALUES` and `INVALID_NAME_TOKENS` define empty-like values such as `N/A`, `-`, and `null`.
- **Personal email domains** — `PERSONAL_EMAIL_DOMAINS` controls which providers are treated as non-corporate in final output.
- **Role inclusion** — `ROLE_INCLUDE_KEYWORDS` lists regex signals for senior marketing candidates.
- **Role exclusion** — `ROLE_EXCLUDE_KEYWORDS` lists regex signals for non-target roles (engineering, finance, HR, etc.).
- **Seniority ranking** — `SENIORITY_RANKING_MAP` and `SENIORITY_LEVEL_PATTERNS` define explicit rank levels (CMO > VP Marketing > Head of Marketing > Director > Senior Manager > Growth Lead > other).

`src/roles.py` and `src/classify_roles.py` consume these config constants. `classify_roles()` materializes `seniority_rank` for explainability; `seniority_rank_for_row()` in `roles.py` prefers that column when sorting during dedupe and company selection.

## Data quality issues observed (assessment dataset)

The provided `linkedin_raw_data.csv` shows typical scrape problems:

- **Names** — extra spaces, ALL CAPS, honorifics (`Dr.`), placeholders (`N/A`, `-`), and a fake “LinkedIn Ads” row.
- **Headlines** — pipes (`|`), “Title at Company”, HTML entities (`&amp;`), mixed marketing vs non-marketing roles.
- **Company** — sometimes blank while the company appears in the headline; inconsistent branding (`Meta Ireland` vs `LinkedIn` vs `LinkedIn Ireland`).
- **Email** — missing values, a phone number in the email column, personal Gmail mixed with corporate addresses for the same profile history.
- **Profile URLs** — occasionally missing scheme (`linkedin.com/in/...`).
- **Duplicates** — repeated scrapes of the same person (`scraped_at` differs).

These observations drive the rule-based cleaning and ranking order above.

## Assumptions and limitations

- **Role rules** are regex-based on headline + derived title; ambiguous “manager” titles are excluded unless they match the documented senior patterns (for example “Senior Marketing Manager”, “Director of Marketing”).
- **Company matching** uses heuristic grouping (strip `Ireland` / `EMEA`, etc.); edge cases may still split or merge organizations incorrectly.
- **Personal email** — if only a personal address exists after deduplication, the pipeline outputs an empty `email` field.
- **`tldextract`** uses the bundled public suffix list (`suffix_list_urls=()`) and a writable cache directory under `task2-data-pipeline/.cache/` so runs do not depend on downloading the PSL at startup.

## Inspection output

Each run prints (`inspect_data` in `src/inspect.py`): shape, column dtypes, missing-value counts, and up to five sample values per column.
